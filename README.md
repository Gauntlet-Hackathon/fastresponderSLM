# fastresponderSLM: the rescue-request tagger

A small, specialist model for offline flood-rescue triage. It reads **one messy rescue request**
(English, Spanish or a mix) and turns it into typed fields, each with a **calibrated confidence**:
location, people count, vulnerable people, hazards, needs, request kind, time reference and whether
it is a request at all. It never decides priority. A deterministic rules engine in the product repo
([Gauntlet-Hackathon/gauntletvshackathon](https://github.com/Gauntlet-Hackathon/gauntletvshackathon))
does that from these fields alone.

```
raw text ──> rescue-tagger (this repo) ──> `extracted` payload + confidences ──> rules engine ──> decision
```

Runs on a field laptop: CPU only, no internet, same input gives byte-identical output.

## Repo layout

| Path | What lives there |
| --- | --- |
| `configs/` | One YAML per stage or experiment (data build now; training next) |
| `src/rescue_tagger/labels.py` | Every label, head and span tag: the single source of truth |
| `src/rescue_tagger/records.py` | The unified training record + `extracted` schema validation |
| `src/rescue_tagger/schema/` | Contract schemas vendored from the product repo (pinned commit) |
| `src/rescue_tagger/data/` | One module per data source, the synthetic generator, leak check, build |
| `data/synthetic/batches/` | Committed synthetic batches (generated once, reproducible by seed) |
| `data/raw/`, `data/processed/` | Downloads and built files (gitignored, rebuilt by script) |
| `tests/` | Schema sync, label mapping, determinism and leak tests |
| `docs/` | Data card, decisions and the experiment log |

Training side: `model.py` (encoder + span tagger + heads), `features.py`, `train.py`,
`calibrate.py` (per-head temperature scaling, ECE), `infer.py` (deterministic CPU extraction, the
module the field adapter wraps), `durations.py`, `evaluate.py`, `publish.py` (Hugging Face Hub,
pinned revision), and `modal_jobs/train.py` (GPU pipeline launched by the `train` workflow).

## Quick start

```bash
uv venv -p 3.12 && source .venv/bin/activate
uv pip install -e ".[data,train]" pytest ruff
ruff check . && pytest                                           # fast checks (what CI runs)
python -m rescue_tagger.data.synthetic --n 50 --seed 1000 --out data/synthetic/batches/b0001.jsonl
python -m rescue_tagger.data.build --config configs/data.yaml    # -> data/processed/
python -m rescue_tagger.train --config configs/train_mmbert_small.yaml --set limit_rows=50 epochs=1
python -m rescue_tagger.calibrate outputs/mmbert_small/best      # fits on dev only
python -m rescue_tagger.evaluate outputs/mmbert_small/best --data data/processed/test.jsonl
python -m rescue_tagger.infer outputs/mmbert_small/best "HELP roof 3 kids water rising Westheimer"
```

GPU training runs on Modal: Actions -> `train` -> pick a config (needs repo secrets
`MODAL_TOKEN_ID`, `MODAL_TOKEN_SECRET`, `HF_TOKEN`).

Environment: `OPENAI_SLM_API_KEY` (synthetic generation), `HF_TOKEN` (dataset download),
`EVAL_REPO` (optional path to a product-repo checkout, so its eval sets are protected from training).

## Overnight training loop

`.github/workflows/loop.yml` runs when a train run finishes (each main-branch train run dispatches it
from its last step) and every 30 minutes. It launches the next experiment from
`configs/loop_queue.yaml` on Modal when nothing is running, one change per run, each from the
original base model. Each run calibrates on one fixed half of dev and is scored on the other half,
then `rescue_tagger.loop` compares it with the current best model (`/runs/champion.json` on the
Modal volume) and promotes it only if every gate passes:

- real-text dev score up by at least 0.5 points (and by more than 2x the seed-to-seed spread)
- no engine-critical field (is_request, needs, vulnerable, location type) down more than 1 point
- calibration error at most 0.10 per field and not more than 0.02 worse than the best model
- identical output across repeats, under 100 ms per request
- the synthetic-vs-real gap no wider than the best model's

The loop stops itself after the run cap, 3 rejections in a row, the gap widening twice, or the same
run failing twice. It ticks whenever a train run finishes, with a cron every 30 minutes as a fallback.
From 12:07 UTC it scores the best model on the test sets and Harvey once; every
such read is logged to `/runs/eval_reads.jsonl`. Test and Harvey are reported with upstream labels
(primary) and with the docs/DATA.md category rules applied (secondary).

To stop the loop, cancel the running train run and the loop tick it starts; a cancelled run is
relaunched once, and the loop stops after the same item fails twice. Test sets are never used to choose between runs.

## Data rules (non-negotiable)

1. Test splits and the sealed holdout (set E) never enter training. `data/leakcheck.py` drops any
   training row that matches eval text, exactly or near-verbatim.
2. Training data is generated by OpenAI models only. Golden set B is drafted by a different family
   (Claude) and checked by a person, so the evals do not just measure the generator.
3. Hurricane Harvey tweets (Houston, 2017) are held out of training as real raw text for golden set B.

See [docs/DATA.md](docs/DATA.md) for every source, its license and how its labels map.
